# 智能排版

设置 → 编辑器 → 智能排版，默认开启。关闭后立即恢复原生断行；选择会写入 `editor.json`，旧配置没有该字段时默认开启。

正文段落使用现有 `tdewolff/canvas/text` 的 Knuth–Plass 算法，依据整段文字的宽度选择断行。Unicode UAX #14 提供中英文断行机会；原生字体塑形负责实际文字、链接、行内代码和公式对象的尺寸。

- 英文只伸展词间空白，上限为原宽度的 50%；汉字/假名间可伸展至 0.12 em。段末行不拉伸，无法在界限内对齐的行保持自然宽度。不压缩字形。
- 标点附近降低伸展预算，标点两侧的作者空格保持自然宽度；仅对无样式 CJK 标点轻微回收边距（最多 0.25 em，至少保留原生 advance 的 70%），不缩放字形。英文标点、代码和行内对象不压缩。
- 不插入空格、换行或其他字符到 Markdown，也不改变复制、撤销和文件内容。绘制、光标、选区和命中测试使用同一组原生行布局，保留 UTF-16/源字节偏移映射。
- 标题、代码块、表格和单独图片保留原排版。正文普通单换行投影为空格，参与整段优化；显式硬换行仍然分行，每个显示行段分别优化。短代码片段保持完整，并约束过短的末行。含制表符或 RTL 文字的段落，以及超过 4096 个 rune 或 512 个断行单元的段落使用原生回退。输入法组合期间保留原生布局。
- 内联代码内部不添加断行机会；短的加粗、斜体、删除线和链接片段（最多 16 UTF-16 单位）也优先保持完整，渲染出的公式是不可拆分的行内对象。暂不提供自动英文连字符、基于字形墨迹边界的完整标点挤压或自动中英文空白。
- 每个编辑器缓存最多 16 个排版结果且合计不超过 16384 UTF-16 单位，避免光标移动反复运行求解器。文本、样式、字体和宽度变化会重算；关闭设置清除这层缓存。

实现：`native/textlayout`；接入：`native/mdedit/layout.go`；设置：`native/nativeui/editor_settings.go`。

验证：`sh scripts/go.sh -C native test ./...`。`native/textlayout` 覆盖连续源范围、组合字符、CJK、行内对象、原生回退、几何一致性与缓存上限；编辑器覆盖开关、命中、输入、撤销和上下移动。`BenchmarkSmartParagraph` 测首次求解，`BenchmarkCachedSmartParagraph` 测结果复用。
