# 笔记库运行时：模块职责与行为记录

Markdown 文件是真源；索引是可重建投影，恢复记录不是替代文件格式。

当前目录与依赖边界以 [architecture.md](architecture.md) 为准；本文入口已按当前模块更新，
较早的实现路径仅用于描述行为背景。

## 模块与边界

- `application/document`：保存、恢复、版本历史和冲突合并用例；`document` 声明数据仓储端口，
  `platform/filesystem/documentstore` 提供具体存储。
- `application/vault`：笔记库 Session、后台刷新/查询、关联笔记与文件操作；`vault/watch` 和
  `vault/index` 承担监听与结构索引，`search` 承担全文查询，具体适配由 `app` 组合。
- `application/workspace` 与 `workspace`：最近文档、工作区恢复用例，以及可持久化的 tab、pane、
  分屏和光标快照；`platform/filesystem/workspacestore` 实现快照存储。
- `nativeui`：将 Session 快照和结果呈现到界面；界面通过依赖注入调用用例，不负责文件存储或
  索引实现。完整依赖方向见 [architecture.md](architecture.md)。

全文索引实现于 `search`，持久索引目录适配于
`platform/filesystem/vaultsearchstore`；搜索/重建的进程资源边界见 [tantivy-search.md](tantivy-search.md)。

## 用户入口

- 侧栏放大镜 / ⌘⇧F：居中笔记库搜索浮层；空输入显示最近笔记，支持全文 / 字面量、方向键、Enter 打开、Esc 关闭；最多显示 500 条。
- ⌘F：当前笔记内查找与替换，保持独立查询文本。
- 文档头更多菜单：恢复草稿、版本历史、关联笔记。
- 草稿/历史恢复打开为未命名副本，保留原文件。
- 外部修改：未编辑的当前文件重新加载；有本地编辑时保留恢复草稿、暂停自动写入，由用户选择加载磁盘或保留副本。

## 数据与并发

保存比较打开/上次保存时的磁盘 revision。冲突时不能把当前编辑自动覆盖到外部新版本上；手动保存也使用同一校验。旧文档的异步保存结果不能清除新文档的 dirty 状态。切换时会使旧保存任务失效，并与正在执行的保存串行化。

原子保存保证 Muse 不将文件截断成半份；版本检查是乐观并发控制。文件系统没有可移植的“比较内容哈希并原子替换”，最终检查与 Rename 之间仍有很窄的外部进程竞态窗口。

自动保存由 UI 帧调度，活动运行时每 100ms 请求下一帧；750ms 是停止输入后的目标延迟，后台/最小化时的实际调度取决于原生窗口事件循环，尚未做机器验收。

## 性能与当前边界

结构快照仍保留源码与派生信息；Tantivy 后端本身仅在 Go 中保留路径和版本清单，正文从 native document store 按需取回。全文走倒排索引；字面量为完整保留短字、标点、跨行及源码字节位置而按小批读索引中的正文再扫描。应用级可重建数据统一存放在 `cachepath.Root()` 下，不放进 vault。默认根目录是 `$XDG_CACHE_HOME/muse`，否则 `~/.cache/muse`；`MUSE_CACHE_DIR` 覆盖完整根目录，测试用该变量隔离到临时目录。Tantivy 索引和网络图片缓存各自使用根目录下的独立类别子目录。

首次构建在后台按 128 篇一批提交，牺牲首次构建速度以限制 native 文档分配峰值。单批提交完成不代表整次操作成功：dirty marker 覆盖整个更新，最终成功才发布清单；中断或清单丢失后隔离缓存、重建。目录级跨进程锁防止恢复逻辑移动正在使用的索引。未保存编辑是每次查询的 overlay，不写索引，不改变磁盘冲突检查。

查询和反链放后台避免同步阻塞 UI，不代表查询耗时与库大小无关。native 单次查询不能由 Go context 在调用中间强行中断，取消在调用前后及字面量批次间生效。尚无可承诺的真实库规模上限。

当前解析支持常见 frontmatter、ATX 标题、块 ID、wiki 和行内 Markdown 链接；尚未覆盖完整 YAML、Setext 标题、引用式 Markdown 链接。没有实现重命名后全库引用重写、链接输入补全、未链接提及、属性管理或笔记嵌入。

不支持的语法应保留原始源码；这批新增索引不改写笔记内容。

## 旧内存搜索合成压测（Apple M3，单次采样）

`go test ./vaultindex -run '^$' -bench . -benchtime=1x`；每文件约 2KiB，1 万文件约 20MiB。创建语料后测试，因此不是冷磁盘读取，也不是 P95 保证。

| 操作（1 万文件） | 耗时 | 每次操作累计分配量 |
|---|---:|---:|
| 重建索引 | 310.6ms | 99.9MB |
| 常见词，前 500 条 | 1.225ms | 413KB |
| 稀疏命中，前 500 条 | 38.36ms | 20.64MB |
| 无命中，前 500 条 | 40.27ms | 20.64MB |
| 反链 | 13.5ms | 11.3MB |

B/op 是累计分配量，不是常驻内存。上表属于旧线性搜索对照，不是当前 Tantivy 数据。当前独立搜索进程的 RSS、索引体积与操作时间见 [tantivy-search.md](tantivy-search.md)。尚未测真实库冷启动、并发查询期间的输入延迟，以及更多文件的资源上限；不要把合成数字当成产品容量承诺。
