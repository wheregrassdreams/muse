# 目录树交互与视觉验收

本文记录目录树完整交互范围与交付验收标准。实现和后续修改都以本文为准。

根级目标参考 VS Code Explorer 接受文件/文件夹拖放的成熟做法：根目录应是清楚、容易命中的目标，而不是隐藏边缘热点。Muse 保持单 vault 模型，不支持树内排序。参考：[VS Code Explorer 行为](https://code.visualstudio.com/docs/editing/getting-started/userinterface)。

## 交互范围

- 明确区分拖动类型：目录树内部移动、拖入编辑区使用 Muse 窗口内的拖动投影；指针离开当前窗口后切换为操作系统原生的窗口间文件拖动交互。原生拖动接管后由系统完成拖放或取消，拖入外部文件仍由系统文件拖放入口处理。
- 点击与拖动必须分开：按下但未超过工具包真实拖动阈值时只执行点击，不能显示投影、删除区或改变任一行；只有指针移动超过阈值并进入 dragging 状态后才显示拖动 UI。
- 普通树行和透明拖动把手均保留手型指针；透明把手不能吞掉点击、右键菜单或 hover 反馈。
- 目录树拖动只用于把文件或目录移动到另一个目标目录，或移动回笔记库根目录；不支持同级排序，也不改变显示顺序。
- 提供明显且容易命中的笔记库根目录目标（参考成熟 IDE 文件树的根级投放：在树视图/根节点任意空白位置可放回根目录，或展示一个明确的根目录投放行）；根目标不能只是一条窄边缘或隐藏热点。
- 把项目拖到其当前父目录时必须严格 no-op：文件位置和显示顺序均不变。树条目之间不提供“调整顺序”投放状态。
- 支持从 Finder 将文件或目录拖入目录树，递归复制到目标目录，冲突时生成不覆盖源文件或已有目标的名称。
- Muse 原生窗口之间拖动要保留项目元数据和 Copy/Move 操作语义：同一笔记库的默认拖放应移动原文件，显式 Copy 意图才复制；不能当成 Finder 外部拖入而复制出重复项。Finder/其他外部来源仍按复制导入处理。
- 支持将树项目拖入编辑区，在指针位置插入可撤销的 `[[笔记名]]` 链接。
- 拖动树项目时仅显示一个圆角矩形拖动投影：图标、文件名、当前操作说明。不能同时显示工具包默认拖动副本和第二个自绘卡片。排版严格按参考：第一行图标与文件名并排且视觉尺寸协调；第二行仅有一条随目标变化的短操作说明（如“移动到「目录名」”“插入到编辑区”“移到废纸篓”）。移动说明必须显示真实目标目录名，不能只说“移动到目录”。不出现“调整顺序”文案。副标题对比度低于文件名、字号略小。禁止把多个操作拼成一串、添加解释性文案或使用英文占位；长文件名需截断而不撑破卡片。
- 拖动多选项时投影块第一行改为叠放文件/项目图标与选中数量（如“2 个项目”），不再显示单个文件名；第二行继续显示唯一的当前操作和实际目标。单项拖动仍显示该项目图标与文件名。
- 指针超过拖动阈值后，拖动投影稍作停顿，再通过时长稍长、具有明显非线性缓动的变形动画横向明显收缩到适合文字内容的较短宽度，并增高以容纳副标题；宽度还要比当前过渡方案再窄一些。左右两端对称向中心收缩，卡片中心保持稳定，不能只从右侧截短。收缩后宽度应小于刚开始拖动时的原始宽度，不能只增高不收窄。仅投影可收缩/变形和动画。真实源项目和树行的尺寸、位置、内容、排列在拖动期间保持不变；不要通过修改源行来伪造投影，也不能挤动其他行。
- 树项目拖入编辑区时，在编辑器实际命中的插入位置显示清晰但克制的占位条/插入指示；指示随指针和文本布局更新，释放时链接插入位置必须与指示一致。离开编辑区、结束或取消拖动后及时清除，不改写原文，也不应遮挡文本或编辑器选择状态。
- 侧栏底部在内部拖动期间出现专用删除投放区，覆盖树内容底部但保留设置齿轮等固定底栏控件的可见和可点空间，并保持四周留白（左右及底边约 10–12 DIP），不顶边。它不是高对比白色实心按钮；默认透明/近透明底，使用低对比灰色细虚线边框；垃圾桶和文字对比度还要比边框再低一档，接近次级/禁用态，只作为弱提示。拖入区域后才稍微提高可辨性、轻微泛红并打开垃圾桶盖；拖出后还原。释放后使用应用可恢复的废纸篓语义。
- 图片文件悬停时显示就近定位的缩略预览 popup，优先放在侧栏右侧、编辑区上层；仅在空间不足时换到左侧或上下方。popup 不得被目录树列表或侧栏裁剪，层级高于编辑区内容，指针可从图片行移动到 popup；避免超出窗口边缘。加载失败时有安静的占位提示。
- 文件和目录提供适配对象类型的右键菜单，包含现有可用的重命名、移动到废纸篓、复制路径、在 Finder 中显示等操作。
- 右键菜单同时提供文件项 Copy/Cut/Paste：右键已选项保留整个选择集，右键未选项先将该行设为单项选择；Paste 到右键目录本身或文件所在目录。路径文本复制仍是独立操作。菜单、标准快捷键和 Vim 键位都 dispatch 相同 Action ID。
- 目录树支持常见文件管理器多选：普通点击选择单项；macOS `⌘` 点击（其他平台 `Ctrl` 点击）切换单项；`Shift` 点击选择锚点到当前项的连续可见范围。修饰键选择不打开文件、不折叠/展开目录，也不丢失当前范围锚点；普通点击恢复单选并更新锚点。右键菜单针对右键项工作，不破坏其余已选项。
- 从多选项启动拖动时，按常见文件管理器行为拖动当前选区；拖放移动/复制/删除只作用于选区中的项目，目录冲突处理逐项且不覆盖。单项拖动行为保持不变。

## 视觉要求

- 沿用 Muse 侧栏的字体、背景、文字、边框、强调色和图标语言；拖动卡片与删除区不能突然变成高对比纯黑横条或像素字体。
- 删除区在默认态低对比、近透明、四周留白；细虚线框保持弱提示，图标和文字还要更淡、接近禁用态。进入状态才略微提高可辨性并做轻微红色偏移和开盖图形变化，不闪烁、不跳布局。
- 拖动卡片为紧凑圆角矩形，保持图标与文件名清楚可读；沿用 Muse 当前侧栏的字体、底色、边框和阴影，避免像素字体、硬黑底和高对比突兀色块。操作文案有层级但不拥挤。缩放/形变过程比当前稍长并使用非线性缓动，减少运动幅度，拖动结束及时收起。窗口边界切换不得闪烁、重复出现两个拖动块或丢失拖动数据。
- 编辑区插入指示使用与当前编辑器一致的强调色/低干扰绘制，指向精确字符边界；有足够可见性但不替代鼠标投影，也不覆盖编辑内容。
- 图片 popup 有清楚的边缘、标题和合适留白，尺寸受限并保持图片比例。
- 需检查深色和浅色主题；不得仅用颜色表达目标状态。

## 面板焦点与键盘操作

键盘操作先经过通用语义动作层，再由面板处理；快捷键只负责把按键映射到动作，不在按键分支里直接改文件、编辑器或焦点。这样编辑器、目录树、搜索、反向链接和后续面板可以复用同一组动作名称，并各自声明支持范围。

- 动作层、面板焦点层与键位消费者分离。`ActionDispatcher` 和 action handler 不读取 Vim/Helix/默认模式，也不包含具体按键；`StandardTreeKeymap` 与 `VimTreeKeymap` 是独立消费者，只输出 `ActionID + ActionContext`。默认键位作为首个消费者实现，Vim 键位之后复用同一组动作；未来可增加用户自定义键位消费者。
- 前缀与多键序列使用通用 `KeySequenceRouter`：注册项是 `[]KeyStroke → ActionID + Values`，解析器本身不认识 `Ctrl+W`、Vim、面板或业务动作。标准键位、Vim 键位、未来自定义键位都通过同一 API 注册；支持任意长度序列、序列共享前缀、待定前缀超时、Escape 取消，以及未知后续键重置后再作为新序列起点匹配。推荐前缀超时 800ms；精确动作与更长序列共享前缀时，等待更长匹配或超时后执行较短动作。

- 每个窗口维护 `focusedPanel`（例如 editor、fileTree、search、outline、backlinks）和面板自己的焦点状态。目录树状态包括当前焦点路径、选择锚点、多选集合及树滚动位置。点按面板内容时更新焦点；将焦点移到侧栏不会打开文件或改变编辑器内容。
- 文件树焦点行需有低干扰但可见的焦点反馈，并与“当前打开文档”和多选高亮区分；Vim/Helix 光标所在编辑器也不能因为树焦点而继续显示为键盘所有者。
- 通用动作使用稳定的语义 ID，例如 `FocusPanel`、`FocusEditor`、`NavigatePrevious/Next`、`NavigateParent/Child`、`OpenFocused`、`ToggleExpanded`、`SelectRange`、`SelectAll`、`Rename`、`CopyItems`、`CutItems`、`PasteItems`、`TrashItems`、`CreateFile`、`CreateFolder`、`CopyPath`、`RevealInFinder`、`RefreshPanel`、`Cancel`。执行前由当前面板检查 `CanExecute(action, context)`；实际键位绑定到动作 ID，面板负责执行并给出错误反馈。菜单、命令面板、键盘入口后续都复用同一 dispatcher。
- 输入框、菜单、对话框等模态控件优先消费键盘输入，不穿透到目录树动作。编辑器拥有焦点时普通按键交给编辑器和 Vim/Helix；文件树拥有焦点时才解释文件树导航键。不能把 `j/k` 作为 App 全局快捷键。
- 焦点、选中项和打开的文档分开：移动焦点不自动打开文件；多选保留范围并让复制、剪切、粘贴、重命名和移到废纸篓作用于完整选区。任何文件操作都必须复用拖放已有的 no-overwrite、路径重映射、缓存失效和打开文件更新逻辑。
- 桌面标准键位：`⌘⇧E`（其他平台 `Ctrl+Shift+E`）聚焦/切换到文件树；树焦点下 `↑/↓` 移动焦点行，`Shift+↑/↓` 扩展连续选择，`←/→` 折叠/展开目录或移到父/首个子项，`Enter` 打开文件或切换目录展开，`Esc` 返回编辑器焦点；`F2` 重命名，`⌘/Ctrl+C` 复制选中项目，`⌘/Ctrl+X` 剪切，`⌘/Ctrl+V` 粘贴到焦点目录（焦点是文件则使用其父目录），`Delete/Backspace` 将选区移到可恢复废纸篓，`⌘/Ctrl+A` 选择当前可见项目。剪切状态必须可见且在粘贴成功后清除；冲突时保留源和已有目标并生成无冲突名称。
- 文件树 Vim 键位仅在启用 Vim 模式且文件树拥有焦点时生效：`j/k` 移动焦点，`Shift+j/k` 扩展选择，`h/l` 折叠/展开或移至父/首个子项，`gg/G` 跳到首/末可见项，`Enter` 打开/切换展开，`C` 关闭当前节点或最近展开父级，`z` 折叠全部，`Tab` 切换当前项目选择，`Ctrl+Shift+I` 反选当前可见项目，`r` 重命名，`y/x/p` 文件项复制/剪切/粘贴，`Shift+Y` 复制相对路径，`d` 移到可恢复废纸篓，`a` 新建文件，`A` 新建目录，`?` 显示当前面板键位帮助，`Esc` 返回编辑器。文件系统变更由 app watcher 自动更新；不映射手动 `R` 刷新。Vim 面板键不能被编辑器 normal mode 同时处理。
- Vim Normal/Visual 状态的面板导航绑定由 Vim keymap consumer 注册：`Ctrl+W h`/`Ctrl+W ←` 聚焦左侧文件树，`Ctrl+W l`/`Ctrl+W →` 聚焦右侧编辑区，`Ctrl+W w` 正向循环可聚焦面板，`Ctrl+W W` 反向循环。序列解析交给通用 `KeySequenceRouter`，结果 dispatch 到 `FocusDirection/FocusNextPanel/FocusPreviousPanel`；当前只有文件树与编辑区，未来 split panel 通过注册相邻面板扩展，不在按键处理器中写死 Ctrl+W 分支。Vim Insert/默认模式不注册这些序列，Ctrl+W 继续交给编辑器。
- Copy/Cut/Paste 的目录树对象使用应用内部的文件项剪贴板，不覆盖用户正在使用的文本剪贴板；复制/剪切均支持当前多选集合。第一阶段不承诺把文件项导出为 Finder/桌面系统剪贴板数据。
- 除鼠标拖放外，不新增同级排序或“调整位置”动作。`Delete/Backspace` 与 Vim `d` 使用可恢复废纸篓，不执行不可恢复删除。

Vim 文件树动作参考 [Neo-tree filesystem 键位](https://github.com/nvim-neo-tree/neo-tree.nvim/blob/main/doc/neo-tree.txt)（`y` 复制、`x` 剪切、`p` 粘贴、`r` 重命名、`d` 删除操作）；面板切换参考 [Neovim Ctrl-W 窗口导航](https://neovim.io/doc/user/windows/)。Muse 将删除映射到可恢复废纸篓，并让剪贴板操作服从本应用的冲突保护规则。

## 验收清单

- [ ] 文件/目录移动成功；不能移入自身或后代；重名处理无覆盖；打开文件和选中路径随移动更新。
- [ ] 根目录目标明确、容易命中；拖项目回根目录能成功。拖到当前父目录严格 no-op，不改变排列或文件状态。
- [ ] 树内拖动不改变同级显示顺序，也不产生排序元数据。
- [ ] Finder 文件与目录复制进入树；目录递归复制；冲突不覆盖；源文件保持不变；跳过符号链接。
- [ ] 两个 Muse 窗口间默认执行 Move 并回拖时，接收方实际移动原文件；源列表与目标列表一致，不出现原路径残留或重复副本。显式 Copy 保留原件；Finder 外部拖入仍复制。
- [ ] 拖入编辑区在准确指针位置插入有效 Wiki 链接；作为一次普通编辑可撤销；既有外部文件拖入行为仍工作。
- [ ] 拖入编辑区时占位/插入条跟随实际文本插入边界；释放后链接位置与指示一致，离开或取消时指示清除。
- [ ] 树内拖动先用 Muse 窗口内的投影；指针离开窗口后切换到系统原生窗口间拖动；拖动内容和最终 drop 数据不丢失，结束/取消后清理投影状态。
- [ ] 原地单击/右键不出现投影或删除区；移动超过真实拖动阈值才开始拖动；点击打开、展开、右键菜单和 pointer 手型反馈均正常。
- [ ] 只有一个拖动投影；第一行图标+文件名，第二行单条目标操作文案，副标题略小且低对比；卡片使用 Muse 字体和表面样式；延迟后投影以稍长的非线性缓动变窄、增高并从两端对称收缩，中心不偏移；用尺寸/位置断言确认宽度收窄且中心稳定；长名称不溢出；源行及其他项目几何不变。
- [ ] 单项投影显示原项目图标和文件名；多选投影显示叠放图标和准确选中数量，并保留单条目标操作文案；无重复投影或错误数量。
- [ ] 对移动、编辑区插入、废纸篓删除各执行一次真实 press→move→release 拖放，断言文件系统/编辑器内容/废纸篓调用确实变化；只显示投影不算完成。
- [ ] 删除区覆盖侧栏树内容底部、但不遮挡设置齿轮等固定底栏控件；左右/底边留间距；默认透明/近透明；图标和文字比低对比灰色细虚线边框更淡；暗/亮主题融入侧栏；图标与默认说明水平居中；拖入后略提对比、微红并开盖，隐藏重复说明以免与跟随指针的投影重叠（投影副标题仍显示“移到废纸篓”）；释放后删除进入可恢复废纸篓。
- [ ] 图片悬停预览显示正确图片、比例和标题；默认位于侧栏右侧且层级高于编辑区，列表/面板不裁剪；靠近窗口边缘时自动换位；指针可移入预览；加载中/失败不破坏树交互。
- [ ] 文件和目录右键菜单均可操作且对象适配；右键不会意外打开或选择错误项目。
- [ ] 右键已选项保留整组选区、右键未选项单选该项；菜单中的文件 Copy/Cut/Paste 与键盘调用同一个 Action ID，粘贴目标目录正确且不覆盖冲突。
- [ ] 普通点击单选并保留打开/展开行为；⌘/Ctrl 点击能切换一个项目；Shift 点击选择锚点至当前可见行范围；修饰键不会触发行的打开或目录折叠。右键已选/未选项分别保持合理上下文。
- [ ] 多选拖动按真实按下修饰键和拖动阈值判定：pointer-down 只记录行与修饰键；未越过阈值时只执行一次普通点击语义；越过阈值后才应用 Cmd/Shift 选择并冻结拖动组。Cmd 按住直接拖动加入该项，Shift 按住直接拖动选择锚点范围；已选组普通拖动保留整组，未选行普通拖动缩为单项。用带按下修饰键的真实 PointerDown→Move→Release 回归和深色截图验收。
- [ ] 多选状态拖动时仅拖动选区，不拖动未选项；目标移动、删除和复制均作用于选区，逐项冲突时不覆盖。
