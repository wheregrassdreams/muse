# Markdown 的阅读样式

参考 Bear 的原生笔记排版，以及 GPT 回复中清晰的正文、标题和列表层级。并非复制某个主题的颜色或字体；编辑区和 AI 回复共享标题、代码、引用、表格的视觉规则。

- 使用系统字体，正文 16 DIP，默认行高 1.75。维持现有栏宽和页面留白。
- H1–H6 的字号比例为 `1.8 / 1.45 / 1.22 / 1.1 / 1 / 0.95`。H1、H2 字重 650，较低级标题 600；靠字号和间距组织层级，减少过重的大标题。
- 缩减装饰性块间距；用户真正输入的空行仍然代表段落边界。列表沿用正文行高，标记对齐文字基线。
- 链接使用重点色派生的颜色与下划线，默认柔红色。正文标签显示为普通文字，文档属性区的彩色标签继续保留。
- 行内代码使用等宽字、正文色和中性灰底，带小圆角及较宽的水平、垂直内边距；不跟随重点色染色。光标进入格式修饰范围时，语法标记使用正文同字体和更低对比度灰色；只有粗体定界符随粗体内容加粗，其他修饰符不额外加粗。行内代码与公式展开时，定界符留在对应的内联容器中，共享连续底色，圆角只出现在整体外沿。代码块使用中性背景和舒适内边距；语法高亮照常保留。
- 引用正文轻度降对比度，配 2 DIP 的细线；表格降低边框对比度、表头使用轻微底色。

## 换行语义

正文和 AI 回复中的普通单换行按 Markdown 软换行显示为空格，参与整个段落的断行。空行分段；行末两个空格、反斜杠换行与 `<br>` 继续强制换行。引用和 callout 保留源行结构，不将 `>` 内的普通单换行合并为空格；代码块按原行显示。

文件内容不变，源字节偏移仍是编辑权威；软换行的显示投影保留前后两个光标位置，复制仍取得原始源码。底层编辑器提供 `SoftBreaksAsSpaces` 选项，Muse 正文和 AI 回复开启它；直接展示源码时保留原行结构。

输入空行时只插入输入的字符，不自动补上下空行。Muse 正文使用 `PreserveTypedLineBreaks` 为本次编辑中填入的空行和用户 Enter 创建的换行保存显示锚点，避免把下一行接上来。锚点随编辑移动，参与撤销/重做；移动光标、切换焦点不会增删它们。它们属于当前编辑会话的显示状态，不写入 Markdown；重新加载文件时按文件本身的软/硬换行语义显示。

标点附近限制对齐伸展，作者输入的空格保持自然宽度；对相邻的无样式全角标点做定向边距回收：开括号左侧、闭括号右侧上限 0.2 em，闭括号后接其他闭括号上限 0.1 em，分隔/闭括号后接开括号上限 0.25 em，且保留至少 70% 的原生前进宽度。代码、作者输入的空格和英文标点不参与该压缩，间距预算不够时保留自然右边缘。表格外框四角为 4 DIP 圆角，内部网格仍是直线。

小节标题前保留独立的段落节奏：H1–H6 的最小上间距分别为 2.4 / 2.3 / 2.2 / 2 / 1.8 / 1.8 em，已有源码空行计入这一距离，不重复叠加。文档开头不添加小节间距，连续标题保持紧凑，标题与后续正文的距离不扩大。

## 实现与验证

共享视觉参数位于 `native/mdoc/typography.go`，编辑器引用同一组标题尺寸、字重和色彩。软换行投影分别位于 `native/mdedit/display.go` 和 `native/mdoc/view.go`；解析模型保留软、硬换行的区别。

测试涵盖软/硬换行、段落与代码边界、复制、源/显示位置往返、编辑撤销及明暗主题组合内容。样式不改写 Markdown。

参考：[Bear 排版选项](https://bear.app/faq/typography-options/)、[Bear 编辑器](https://bear.app/faq/how-to-use-bears-editor/)。
