# 笔记库链接、图片、搜索与括号自动补全验收方案

## 目标

把单文件 playground 扩展成可重复使用的真实目录型笔记库样例，并以该样例贯穿验证笔记解析、链接交互、图片加载、全文搜索和编辑器补全。测试要覆盖多层目录与真实图片文件，不以孤立的解析器单测代替端到端行为。

同时实现 Obsidian 风格的 wiki 链接建议弹层，以及安全字符的自动配对；首批自动配对只做方括号 `[]`。

追加：GIF 必须按帧自动播放；增加一个稳定的网络图片案例和下载/重开缓存验收。应用需要统一的可重建缓存根目录：默认使用 `$XDG_CACHE_HOME/muse`，未设置时为 `~/.cache/muse`；`MUSE_CACHE_DIR` 覆盖完整根目录，测试必须指向专用临时目录。缓存根目录面向所有可重建数据（例如 Tantivy 索引、网络图片下载及未来缓存），不能只为图片新增专用目录。

## 参考行为与 Muse 决策

Obsidian 官方说明：输入 `[[` 会显示可选文件建议；链接可包含从库根开始的文件夹路径、标题/块锚点及 `|` 显示名；在链接前加 `!` 表示嵌入。普通内部链接可悬停预览。反链至少展示指向当前笔记的已链接提及；Obsidian 另有未链接提及，但这不属于本次验收范围。搜索面向整个 vault 的笔记内容。

参考文档：[Internal links](https://obsidian.md/help/Linking%2Bnotes%2Band%2Bfiles/Internal%2Blinks)、[Embed files](https://obsidian.md/help/Linking%2Bnotes%2Band%2Bfiles/Embed%2Bfiles)、[Backlinks](https://obsidian.md/help/Plugins/Backlinks)、[Page preview](https://obsidian.md/help/Plugins/Page%2Bpreview)、[Search](https://obsidian.md/help/Plugins/Search)。

本轮具体约定：

- `[[note]]` 是普通链接；`![[note]]` 是嵌入。普通链接点击后打开目标；鼠标停留约 450ms 后显示目标预览 overlay。嵌入内容不触发该悬停预览。
- `[[folder/note]]` 从 vault 根解析；不带路径时，沿用现有 Muse 解析规则并以确定性路径排序处理同名目标。相对 Markdown 图片路径先相对当前笔记，再按已有 vault attachment fallback 处理。路径不得逃逸 vault 根。
- `[[image.png]]` 这类非嵌入附件链接也必须可选中和解析；普通点击图片附件打开图片预览。`![[image.png]]` 才在正文中显示图片。
- 普通图片附件链接悬停超过阈值也显示小型图片预览 overlay；直接点击仍打开完整图片预览。任何 `![[...]]` 嵌入都不触发链接悬停 overlay。
- `![[note]]` 必须显示目标笔记的 Markdown 内容，作为只读嵌入块；目标的 Markdown 源码仍只由目标笔记拥有，宿主里的 `![[...]]` 是唯一可编辑源范围。嵌入内容不能伪装成额外的宿主源码字符，也不能让 caret/selection 落入目标笔记文本。
- 链接目标解析和索引解析应保持一致；扩展显示名、标题锚点时不破坏源文本编辑。建议弹层支持键盘上下选择、Enter 接受、Esc 关闭、鼠标点击选择，以及继续输入过滤。
- 补全弹层除上下键外支持 Emacs 风格 `Ctrl+N`/`Ctrl+P` 向下/向上移动；笔记与图片候选使用不同的非 emoji 图标。
- UI 显示笔记路径时以 vault 根为相对基准，不把 vault 目录本身（例如 `vault/Home.md` 的 `vault/`）重复显示。
- 普通 wiki 链接的悬停 overlay 显示目标经过 Markdown 排版后的内容，包括标题、段落、行内格式、链接和图片；不能把源码/纯文本截取当作最终预览。
- 导航树的文件和目录条目允许通过紧凑的右键图标选择器换图标。选择器参考 macOS emoji 面板的紧凑尺寸与交互，图形采用项目现有 Lucide 线条风格；图标选择按 vault 与库内相对路径保存到共享应用缓存目录，重启后仍可恢复。
- `[]` 输入 `[` 后插入 `[]` 并把光标放在中间；再次输入 `]` 时跳过现有闭括号；空配对内退格同时删除两侧。非空内容退格只遵循编辑器现有删除语义。自动配对只在普通文本上下文生效，不在代码/链接等受保护语法中误触发。
- 全文搜索要求覆盖 vault 所有可索引 Markdown 笔记（包含子目录），更新/删除后结果同步；图片附件本身不作为正文全文索引。

## 固定验收语料

使用 `native/testdata/vault-fixture/` 作为固定 fixture，以独立目录作为一个 vault；`scripts/play.sh` 应复制整库到临时运行目录，以 `Home.md` 打开并把整个副本设为 workspace：

```text
native/testdata/vault-fixture/
  Home.md
  Projects/Atlas/Overview.md
  Projects/Atlas/Design Notes.md
  Journal/2026-11-12.md
  Attachments/landscape.webp
  Attachments/diagram.png
  Attachments/photo.jpg
  Attachments/animation.gif
  Assets/duplicate-name.png
```

语料至少包含：多篇 Markdown 笔记、两层以上子目录、指向根目录及子目录笔记的双链、别名链接、标题链接、相互反链、至少一条未解析链接；文内图片与独立图片段落都覆盖。四种扩展名必须对应有效且可解码的真实文件。公开下载图片时在 `ATTRIBUTION.md` 记录原始 URL、作者/来源、许可和本地文件名；优先使用明确标注可再分发的 Wikimedia Commons 文件，并固定内容避免测试依赖运行时网络。

重复文件名用来确认路径优先级确定且结果可解释。另有一个不存在附件引用，验证缺图状态。fixture 是测试数据，不应在测试时被写入；需要修改的场景复制到临时目录。

远程图片用 `httptest` 提供本地 HTTP 图片响应，保证覆盖真实 HTTP 下载、磁盘写入和缓存重开，同时不依赖公网可用性。所有相关测试设置 `MUSE_CACHE_DIR=t.TempDir()`，并确认图片与搜索缓存都只写入这个根目录。

## 验收矩阵

| 范围 | 验收动作 | 通过条件 |
|---|---|---|
| 库加载 | 以 fixture 根目录打开/索引 | 子目录笔记完整进入索引，隐藏目录或 vault 外路径不会泄漏进来 |
| 路径解析 | 从不同子目录解析根路径、相对路径、扩展名省略、别名、标题锚点、同名文件 | 目标符合本方案规则；失败目标保持可识别的未解析状态；不越过 vault 根 |
| 反链 | 打开被引用笔记并查看反链区域 | 所有链接来源各出现一次，来源可点击打开；变更/删除源笔记后反链更新 |
| 普通双链 | 在编辑区点击 `[[...]]` | 打开正确目标；别名显示与目标分离；目标标题/别名可定位 |
| 嵌入 | 渲染 `![[note]]` 与四种图片格式 | 笔记内容可见；四种图片都实际解码绘制；不显示为普通链接，也不出现链接悬停预览 |
| 图片路径 | 使用笔记相对路径、vault 根路径和裸附件名 | 解析到预期文件；同名时确定性；缺失文件显示统一找不到状态 |
| GIF 播放 | 在编辑器、文档预览、图片全屏预览及链接缩略图中打开多帧 fixture GIF | 解码后帧自动按延时循环播放，帧切换会刷新视图；不能只显示首帧 |
| 网络图片缓存 | 打开一张测试用远程图片，断网/重开后复查 | 首次下载成功并落入应用缓存；重开优先使用缓存且内容正确；测试缓存与用户缓存隔离 |
| 缓存根目录 | 不设环境变量与设置测试专用目录分别启动 | 默认符合 XDG cache 目录；环境变量覆盖全局根目录，搜索索引、网络资源等重建数据都落在该根目录下 |
| 链接预览 | 鼠标悬停普通 wiki 链接超过阈值，再移开/点击 | 延迟后显示目标内容 overlay；移开取消或关闭；点击仍是导航；嵌入排除 |
| 建议弹层 | 输入 `[[`，再输入筛选字符 | 弹层位置贴近光标，建议包含可链接的笔记及附件目标并随输入过滤 |
| 建议选择 | 上下键、Enter、Esc、鼠标选择 | 高亮稳定、接受后生成有效链接且光标位置合理；Esc 不改源文本；点击外部按现有 popup 约定关闭 |
| Emacs 补全导航 | popup 打开时按 `Ctrl+N`、`Ctrl+P` | 选中项分别向下、向上移动，边界行为明确且不会输入控制字符 |
| 候选图标 | 弹层同时显示笔记和图片建议 | 两种类型有清楚、非 emoji 的不同图标，图标不影响路径文本和鼠标选择 |
| Vault 相对路径显示 | 打开 fixture 中的 `Home.md` 并查看标题/文件路径 UI | 只显示相对库根路径 `Home.md`，不能把 vault 目录名显示成路径第一段 |
| 渲染后链接预览 | 悬停含标题、粗体、列表、链接和图片的普通 wiki 链接 | Overlay 显示排版后的内容，样式与文档预览一致；不展示 Markdown 原始标记；点击目标仍可正常导航 |
| 导航树图标 | 右键文件和目录，选一个 Lucide 风格图标，重启并重新打开同一 vault | 菜单紧凑且接近 macOS emoji 选择面板的密度；选择后树中显示新图标；状态只写共享缓存目录并按 vault/相对路径隔离，重启仍保留 |
| 自动配对 | 普通文本输入 `[`、键入内容、输入 `]`、空对退格 | 自动补出 `]`、光标在内、可跳过闭符、空对成对删除；受保护语法无误配对 |
| 笔记嵌入 | 渲染 `![[Projects/Atlas/Overview]]` | 目标正文作为只读 Markdown 块显示，不能改变目标文件；嵌入本身不弹 hover preview |
| 全库搜索 | 搜索只存在于深层笔记的唯一词，再修改/删除该笔记复查 | 全库初次可搜；保存/监视更新后旧词消失、新词出现；结果打开正确子目录笔记 |
| 图片回归 | 打开编辑器和文档预览查看 fixture | 视图中的像素与文件格式正确，不因附件缓存或 overlay 状态串图 |

## 实现拆分与验收交付

实施前先读取当前工作区状态，保留所有已有修改。各 worker 只编辑分配范围，不重置、暂存、提交或回滚他人改动。

1. 语料与路径/格式验收：fixture 文件、图片许可记录、解析/渲染集成验证。
2. wiki 输入建议 popup：编辑器内触发、筛选、键鼠选择与接受。
3. 链接交互：普通链接点击、延迟悬停预览 overlay、嵌入排除及反链目标跳转。
4. 方括号自动配对：`[]` 插入、跳过、成对退格及上下文保护。
5. 全库搜索：使用同一 fixture 验证初次建立、目录覆盖、变更和删除。
6. 图片与缓存：GIF 解码/播放、网络下载落盘、缓存命中，以及应用级 XDG/环境变量根目录。

集成验收由主 agent 负责：检查各自实现是否遵守同一套路径和嵌入语义，跑定向 Go 测试、整个 native 测试集及 `git diff --check`；再实际启动 Muse 打开该 fixture，检查 popup/hover/图片等 UI 截图与交互。测试结果要记录命令和实际结果，不把静态检查当作 UI 验收。

## 当前实现基线

- 已有 `native/vaultindex` 支持笔记、标题、别名、双链、反链和 vault 内路径解析；`native/vaultsearch` 是持久化 Tantivy 全文索引。
- 编辑器已有 wiki 链接渲染与点击回调；图片解析已有相对路径、vault 根和裸附件名 fallback。
- 已知缺口包括 wiki 链接输入建议、链接悬停预览和目录型多格式图片验收语料。本轮需用 fixture 实际验证已有逻辑，并修复复现的问题。
