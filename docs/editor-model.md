# 编辑器模型：源码是唯一的真实状态

- **状态**：现行（2026-11-09）
- **相关**：[rfc-001-editor-engine.md](rfc-001-editor-engine.md)、`native/mdedit/`
- **适用范围**：正文编辑器的源码表示、叶片模型、光标寻址、显示映射、性能边界

本文记录 `native/mdedit` 的模型与不变量。改动编辑行为前先读它：这里的每一条都是为了“打开的 vault 不被改坏、双链可用、编辑行为与原始 Markdown 一致”。

---

## 1. 分层

```
source (string)            唯一的真实状态，字节偏移就是光标
  ├─ mask                  前置元信息、%%备注%% 用空格占位，长度与换行不变；
                           注释在行首（块内容开头）时第一个字节换成不换行空格，
                           否则那串空格会被解析成缩进代码块，把行切成两半
  ├─ parser.Document       位置化 CommonMark 解析（mygo/markdown）
  └─ leaves []*leaf        文档的行：块 + 空行
        └─ units []*leaf   光标可以停的单位（表格的行拆成单元格）
             └─ pieces     源码 → 显示 的映射，一个叶片一份
```

**解析输入只有一个所有者**（`mdedit/parsed.go`）。`parserSource` 持有解析器读到的一切和由源码派生的状态：`doc`、它据以构建的 `src`、屏蔽后的 `mask`、`mask` 里藏起来的 `comments`、前置元信息的结尾 `fm`。只有它的三个方法能写这些字段——`set`（整篇重读）、`edit`（跨一次编辑推进）、`clear`（换了源码，或根本不当 Markdown 解析）；`Editor.sync` 是唯一决定走哪条路的调用方。新增一个派生字段时，它只有这两个地方要填，而"只在增量路径更新、忘了整篇路径"这类错误由 `TestTheParserSourceIsWrittenInOnePlace`（读本包源码找写入点）和随机按键测试里"派生状态必须等于重算"的断言一起拦。

四条不变量：

1. **源码是唯一状态。** 没有独立的“富文本树”。显示、光标、选区、撤销都从 `src` 派生；一次编辑就是一次字符串替换（`history.go: replace`）。
2. **光标是源码字节偏移。** `caret`/`anchor` 是 int，不指向节点。任何“块内位置”都能还原成一个偏移，反之亦然。
3. **文档的每一行都能被寻址。** 文档的第 N 行在编辑器里就是一个可停靠的位置——包括空行（见 §2）。
4. **显示是源码的投影。** 每个叶片记着它覆盖的源码区间，`pieces` 说明哪段源码显示成什么（隐藏标记、图片对象、`[[双链]]` 的标签）。光标落在某个边界上时，该处的标记“展开”成源码（Obsidian 的 live preview），这只是**显示**变化，不改变编辑行为。

## 2. 叶片：行就是行

`leafKind` 有两类：

- **块**：段落、标题、代码、公式、HTML、表格、分隔线、原始行。
- **行**：`kBlank`（源码里的空行）、`kPhantom`（源码里还没有、光标要写进去的空段落）。

`kBlank` 是 2026-11-09 补上的模型修正。在此之前空行不是叶子，而是两个块之间的“间距”：

- 布局按行高补 `gap`，方向键整块跳过，回车在空行上无效，退格一次吃掉整段空白；
- 结果就是“文档第 5 行”在编辑器里不存在，只有一个视觉上的缝。

现在的规则（`doc.go: addBlankLeaves`、`layout.go: layoutDoc`）：

- 每个空行生成一个零长度、行高、零外边距的 `kBlank` 叶；文档开头、结尾的空行同样成叶。
- 空行不 shaping（没有文字可排），只在它载着输入法组合文本时排一次（`layoutDoc` 里 `e.composing` 那一支）。
- 空行**拥有自己的偏移**：`unitIndex`/`leafIndex` 里行叶优先于结束于同一偏移的块（`nav.go`、`editor.go`）。
- 于是：`Enter` 插一个换行、`Backspace`/`Delete` 一次只吃一个换行、方向键逐行走、点击/选区/输入法锚点都落在这一行。
- 一个块紧跟空行时，块从下一行开始，不再叠加自己的外边距：**布局的行与文档的行一一对应**。`"a\n\nb"` 的三行 y 是 `[35.2 63.2 91.2]`。

**空行的归属看它自己带的标记**：`>` 越过一层引用，`> >` 两层；裸空行不属于任何容器，它就是第 0 列的一行。所以

- callout 里 `>` 的间隔行是 callout 的行：光标落在 `>` 之后（`start` 是标记之后），缩进到正文列，Enter 补 `> `，退格/Delete 一次吃掉一整行（标记+换行）；
- 列表项、脚注里的空行不带标记，是文档级的一行：光标停在列首，打字就写在列首——这是原始语义，Obsidian 里也一样（写在那儿会让列表项结束）。

`quoteChain` 决定了它属于哪条引用链：从相邻叶片的容器链里取到第 depth 层引用为止，所以 `- > a` 这种“项里的引用”也能拿到 item+quote 两层的缩进。

**Enter 只写一个换行**（Obsidian 的语义，见 §4）：段末、标题末、引用末、列表末都一样，容器跟着续行（列表续 `- `，引用续 `> `），Shift+Enter 与 Enter 完全相同。所以"一个 Enter 一行、两个 Enter 分段"在任何块里都成立，不会因为块种类而多出空行；文档末尾的那一行也是真正的空行叶，光标回车后直接落在它上面，打字不会跳行。

`kPhantom` 只保留给源码里确实没有行的地方：**完全空的**源码（`src == ""`），以及点击/下移到代码、表格、分隔线下方那种"没有行可停"的位置。它的 `pre` 也是一个换行。

两点推论，都是模型层面的、不能互相替代：

1. **换行是内容**。一个只有换行的文档（`"\n\n"`）不是空文档：它有自己的那几行（空行叶），占位提示不显示。只有 `src == ""` 才是"空"。
2. **占位提示是固定位置的**：它画在文档第一行，不跟着光标走——光标可以移动，提示标记的是"这个笔记还是空的"。

phantom 一旦落到源码里已经有行的地方就退位（`lineAt` 命中就让 `e.phantom = nil`），因为那一行现在由源码持有。

## 3. 原子对象

- **表格**是一个叶，单元格是单位（`units()` 把行拆成 cell）。光标在单元格之间移动，`Tab` 下一格，上下键同列。
- **图片**在“独占一段”时排成块对象（`aloneImage`），光标进入就展开成 `![](...)` 源码。
- 表格/图片的“点一下整体选中，再点 source 按钮才展开源码”这一层尚未实现（P1）。

## 4. 与 Obsidian / Typora 的对应

| | Obsidian（CM6） | Typora | Muse |
|---|---|---|---|
| 缓冲区 | 连续文本 | 块列表 + 临时空段落 | 连续源码 + 块叶 |
| 标记隐藏 | replace decoration | 块内渲染 | 叶片的 `pieces` |
| 空行 | 是一个字符位置 | 不存在（块间距） | `kBlank` 叶 |
| 原子对象 | atomic range | 块级对象 | 图片对象 / 表格单元格 |
| 编辑语义 | 原始文本 | 有“智能”转换 | 原始文本（`Enter` 一个换行、`Backspace` 一次一个换行） |

Muse 用的是**块叶模型去逼近连续缓冲区**。差别落在“寻址”上：CM6 里每个字符偏移都是一个合法光标位置，块模型里只有叶片的边界是。补上 `kBlank` 之后，顶层文档的每一行都可以寻址了，剩下的近似见 §5。这也是为什么编辑行为要保持原始语义：显示层可以近似，编辑层不能。

## 5. 已知近似（写代码的人要知道）

1. **注释里的行不成叶**：`%%…%%` 里的行被 `insideComment` 过滤掉，注释按“折叠”处理——它不占布局的行，点进它所在的区域才把光标放进注释里、注释才展开（`gapPhantomAt` 的最后一个用途）。
2. **段末的 phantom**（只在上面说的位置出现）在布局上占一行，位置直接取上一块之下的一行。
3. **引用里的空行按 Enter 会结束引用**：删掉标记（文档末尾还会补一个空行，否则下一行会被解析成引用的懒续行）。这是“离开容器”的唯一手段，和列表项上再按一次 Enter 退出列表同一个意思。

## 6. 参考系：哪些有先例，哪些是自研的

这一节是给"以后改模型的人"看的：每条设计对应哪个理论或实现，**有先例的照抄它的不变量**，自研的写清它依赖的前提。判据不是"谁更优雅"，而是"能不能指着某个实现说：它也是这么做的，而且它踩过的坑我们不用再踩"。

### 6.1 有理论、有成熟实现（照抄不变量）

| 设计 | 先例 | 该抄的不变量 |
|---|---|---|
| 源码是唯一真实状态，光标是字节偏移，显示是投影 | **projective vs projectional editing**（文本为真 vs AST 为真）；[CodeMirror 6](https://codemirror.net/docs/ref/) 的不可变 state；VS Code 的 [piece tree](https://stackoverflow.com/questions/46785220/which-data-structure-used-in-visual-studio-code) | 编辑只能经由"一次源码替换"发生；显示是从源码算出来的，不反向成为状态 |
| 行内的"隐藏标记、光标进入才展开" | Neovim 的 `conceallevel` / `concealcursor`（[render-markdown.nvim](https://github.com/MeanderingProgrammer/render-markdown.nvim) 就是这套）；Emacs 的 `invisible` text property；CM6 的 `Decoration.replace` | 只展开光标所在的那一个构造；展开与否不改变编辑语义 |
| 对象替换符 + 给它的盒子 | Unicode **U+FFFC** OBJECT REPLACEMENT CHARACTER（[码表](https://www.unicode.org/charts/PDF/UFFF0.pdf)）；Cocoa 的 `NSTextAttachment` | 对象在文本里占一个字符的位置，盒子由排版给它，不走"插入一张图"的旁路 |
| phantom：光标需要一个源码里没有的位置 | ProseMirror 的 **GapCursor**（[README](https://app.unpkg.com/prosemirror-gapcursor@1.4.0/files/src/README.md)）与 `trailingNode` | **一旦某个节点能容纳光标，gap 必须让位**——这条我们第一版没抄，于是出现"占位提示跟着光标走""空笔记退格后点一下崩" |
| 增量解析 + "派生状态必须等于重算" | 增量解析（Wagner & Graham；tree-sitter 的 incremental reparse）；**differential testing / oracle 测试**（McKeeman 1998，[论文](https://www.hpl.hp.com/hpjournal/ddj/vol10num1/vol10num1art9.pdf)）；rust-analyzer 的 salsa（memo + 依赖失效） | 快路径必须与整篇重算逐字段相等；所有权集中在一处（`parserSource`） |
| UTF-16 偏移换算 | 平台文本单位就是 UTF-16（Cocoa `NSRange`、Win32）；字形簇按 UAX #29 | 编辑落在字形簇边界上；换算索引增量维护 + 对拍 |
| 按键/帧预算 | RAIL 模型、输入延迟预算；Zed / Helix 的帧时间实践 | 按键路径不许出现整篇文档的操作；测量用 CPU 时间（墙钟会被别的进程污染） |

### 6.2 移植（block 模型这一层）

叶子模型（块、单元、行）来自 **ProseMirror 的 document model**（schema / `atom` / `NodeSelection` / transaction），Typora 的块模型也是同一类。我们借的是它的形状，不是它的 schema：Markdown 的块种类由解析器决定，编辑器不定义 schema。

### 6.3 自研（写清前提，别当成定论）

1. **空行成叶**。没有先例：块编辑器把空行当块间距，CM6 不需要建模（每个偏移都是位置）。我们的做法是把 CM6 的性质"每个偏移都是位置"**翻译**成块模型——设计问题因此变成"位置集合是否覆盖用户能寻址的东西"，答案是"行"。前提：编辑器要保留原始 Markdown 的编辑语义（用户按 Enter 就是加一行）。代价：容器前缀、行高、和 phantom 的关系都没有参考实现，前两轮 bug 全在这里。
2. **注释的等长 mask**（把 `%%…%%` 换成空格再喂解析器）。这是**适配层，不是设计**：mygo 的 `parser` 只暴露 `Extensions` 位标志，没有注册自定义 inline/block 解析器的入口（见 `ui/markdown/parser/document.go`），所以 `%%` 无法作为解析器扩展表达。前提就是"parser 不可扩展"——如果哪天它支持了（或我们自己加一条 inline 规则），这一层整层删掉，只留 decoration。
3. **单位 = 单元格**（表格）与"表格整体也可整体选中"。Obsidian 的表格同样是按单元格编辑、用一个 source 按钮看原文；我们没有它的实现细节可抄，所以按"单元格是光标可达的最小单位"来定。

### 6.4 用这条判据看历史 bug

- "一个 Enter 两个换行"：不是实现错，是**底座错**（Typora 的段落语义）。Obsidian 文档写明 Enter 只写一个换行（[Basic formatting syntax](https://obsidian.md/help/syntax)），改了底座之后这类 bug 没有立足点。
- "占位提示跟着光标"、"空笔记退格后点击崩"：GapCursor 的让位不变量缺席。
- "注释被编辑后露出 markdown"：同一套屏蔽规则有两份实现（违反 6.1 最后一条"所有权集中"）。

## 7. 性能边界

按键路径（一次按键 = 编辑 + 解析 + 排版 + 一帧）里不允许出现整篇文档的操作。`TestTypingFrameBudget` 是这条线的闸门：1MB 文档、按键中位数 < 8.3ms（120fps），CI 上放宽到 16ms。

这个闸门读的是时间，而 `go test ./...` 会把各包的测试并排跑在同样的核和内存带宽上——同一次按键单跑是 4.7ms，并排时读到过 14ms。所以它默认跳过，需要时单独跑：

```
MUSE_PERF=1 go test ./mdedit -run TestTypingFrameBudget -v
```

量的是 **CPU 时间**（darwin/linux 用 `getrusage`，其他平台退回墙钟），并且最多重测三轮：机器忙的时候，晚一拍的读数不该算成编辑器慢。

当前实测（Apple M3，1MB）：

| 操作 | 耗时 |
|---|---|
| 一次按键（中位数，CPU 时间） | 3.7-5.3ms |
| 光标进出 `%%注释%%` | ~1.1ms（不重解析，只重建叶） |
| 输入法 UTF-16 偏移 | 增量维护，O(编辑长度) |

已经被这条线打回过两件事，都是“整篇文档”的活混进了按键路径：注释展开时的重解析（7ms）、输入法 UTF-16 索引每次重读全文（1.3ms）。以后加功能先问一句：这次按键扫了全文吗？
