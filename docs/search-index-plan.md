# 搜索索引验证与接入边界

本文记录第一轮 Bleve 隔离验证及当时的接入边界。用户随后授权实验接受 CGO，并改为接入 Anytype 的 Tantivy 绑定；当前构建和实现说明见 [tantivy-search.md](tantivy-search.md)。下文无 CGO 闸门及后续 Bleve 优化建议属于历史阶段，不再是当前选型要求。

Bleve 实验位于 `experiments/searchprobe/`，使用独立 Go module，保留用于对照，不作为产品依赖。

## 首轮结论（2026-11-10）

已实现固定 Bleve v2.5.7 的实验、逐文档持久快照、更新删除/重开、每次查询独立的 buffer 覆盖、CJK 普通检索及保留 UTF-8 字节位置的字面量扫描。命令、原始输出与完整限制见 [实验说明](../experiments/searchprobe/README.md)。

Apple M3，1 万篇各 2KiB 的中英混合合成语料，单次热采样：普通稀疏/无命中约 0.12/0.11ms，普通常见词约 6.3ms；构建并关闭约 1.96s，单篇持久更新约 210ms，重开并关闭约 182ms。独立 CLI 运行索引文件约 242MB，约为正文的 11.8 倍，构建累计分配约 2.3GB。累计分配不是 RSS，也不是峰值；后台合并会干扰单次采样。

**本轮不据此正式替换。** 默认字段存储、term vectors 与实验保存的源码快照存在重复；单篇更新仍复制文档 map、重写 ID 清单；普通查询取全量候选再截断；字面量仍线性扫描，无命中约 160ms。这些都是实验适配层或配置的成本，不能直接当作 Bleve 的能力上限。

下一阶段应先关闭不需要的存储/term vectors、去除全库 manifest 更新、减少普通查询候选物化与重复创建空 overlay，并缓存字面量规范化文本。使用统一中英文语料与相同查询契约比较多轮分布、索引空间、构建峰值和更新延迟，再决定接入或更换候选。协作仍停留在接口设计，没有实现同步协议。

## 查询契约

现有 `vaultindex.QueryLimit` 是 Unicode 小写后的子串匹配，按路径排序，每个命中返回原始源码的 UTF-8 字节区间；500 是命中数量上限，不是文档数量。正文包含 Markdown 原文与代码。不能用分词检索无声替代这个契约。

候选全文引擎使用字段 title、path、tags、aliases、body，普通查询允许相关性排序；字面量查询独立保留子串语义。CJK bigram 不等于中文语义分词，也不天然保证单字和任意片段命中。实验必须分别覆盖普通检索、中文短查询、字面量及大小写映射。

## 数据管线

文件发现与监听归 vault 层；Markdown 元数据归解析层；全文引擎只接收已有快照，不自行遍历笔记库或重复读取源文件。

建议接入时传递 `DocumentID + revision + path + metadata + source`。DocumentID 不依赖可变路径；revision 表示快照版本，不能把磁盘哈希当作协作引擎版本。后台结果必须携带工作区代次与查询代次，阻止旧结果覆盖新状态。

持久索引只保存已确认的磁盘快照。未保存编辑是运行时覆盖层：查询时遮蔽对应的旧文档，再合并当前 buffer 的命中；不能把未保存内容作为磁盘真源持久化到索引。索引可随时删除重建，不承担草稿恢复。

磁盘事件先合并，再一次读取、一次解析，同时更新元数据和全文索引。自身保存记录 revision，避免反馈事件重复读写；仅元数据快速过滤不足以保证外部修改判定正确。错误/队列溢出必须触发可观测的重扫，不能悄悄保留陈旧索引。

## 验证闸门

- 固定引擎版本，`CGO_ENABLED=0` 构建与测试；禁用需要 FAISS 的向量扩展。
- 更新、删除、批量变更、关闭重开；确认源文件不被实验改写。
- 对比 1k/10k、每篇约 2KiB 的构建、常见/稀疏/无命中、单篇更新和重开成本。
- 明确区分每文档全文结果与现有逐位置命中；只有相同语义、相同上限的数字可直接比较。
- 累计分配量不代表 RSS，重开不代表冷启动，合成测试不代表真实笔记库上限。正式接入前还需测峰值内存、磁盘体积、冷启动及查询并发时输入延迟。

## 协作边界

在线协作允许额外的 DocumentSession 运行时状态，编辑器通过文本增量事务连接，不改变 Markdown 文件格式。会话重连先核对会话标识与版本，不一致时同步快照；离线多端独立编辑后的自动合并不属于这一阶段。协作引擎尚未选定；本轮接受 CGO 的决定只用于搜索接入。
